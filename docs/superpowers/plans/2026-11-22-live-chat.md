# Live Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A YouTube broadcast that is live now shows its live chat beside the player, following the viewer's position in the DVR window.

**Architecture:** One poller thread per broadcast (on `AppContext.live_chat`) polls YouTube's `get_live_chat` and fills a bounded buffer of parsed messages with sequence numbers and send times. `GET /api/live/{video_id}/chat?behind_ms=&after=` filters the buffer at `server_now - behind_ms - edge_lag_ms`. The browser polls it every 2 s and renders the existing `ChatReplayPanel` in the existing placements.

**Tech Stack:** FastAPI, yt-dlp 2026.10.26 helpers, threading, React 18 + TypeScript, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-21-live-chat-design.md`

## Global Constraints

- Never saved; never reaches YouTube under `HORDE_E2E`; no YouTube call while `ctx.chat_replay.seconds_paused() > 0`.
- One poller per broadcast; it stops 60 s after the last read, when YouTube sends no further token, on a rate limit, and at shutdown (joined). The buffer is dropped 10 minutes after the last read.
- Buffer: at most `LIVE_DVR_WINDOW_SEC` of send time and 20 000 messages.
- Top chat (the watch page's default token). Message parsing reuses `parse._item`; `offset_ms` holds the send time in epoch ms.
- Error codes as chat replay: `youtube_rate_limited`, `youtube_unreachable`, `chat_replay_unavailable`.
- Interface wording: panel heading "Live chat"; note "Chat from before HH:MM isn't available."; the toggle label becomes "Show live chat".

## Review Focus

1. Two viewers of one broadcast: one poller, both see the same messages. → Task 1 test.
2. A viewer scrubbing back past the newest message shown: the list reloads at the new cutoff, not at the edge. → Task 3 model test, Task 4 e2e.
3. The broadcast ends mid-watch: the buffer keeps being served, nothing polls. → Task 1 test.
4. Background tab reading once a minute: the poller restarts on the next read and the buffer keeps its sequence. → Task 1 test.
5. A deleted message already on screen disappears. → Task 1 and Task 3 tests.
